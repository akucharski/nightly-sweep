Documents

How the nightly site sweep works, what each finding means, and how to run and administer it.

1. What this is

The sweep finds pages on a public website that have quietly stopped being true, and tells a person about them. It never changes the site: it reads public pages the same way any visitor does.

It looks for six kinds of problem:

  • Stale pages: not edited in a long time (18 months by default).
  • Outdated wording: past dates still written as if they are ahead, such as “Registration closes May 15, 2024”.
  • Contradictions: two pages, or one page, stating incompatible facts, such as two different fees for the same permit.
  • Dead pages: addresses that answer 404 (not found) or 403 (forbidden).
  • Broken links: links on a page that lead to an error.
  • Expired events: events marked up with an end date that has passed.

For flagged pages, an AI model gives a verdict: is the page still doing its job (live), describing something that has ended (dead), or impossible to tell (unclear)? Age alone is never treated as a problem. A city charter from 1998 can be perfectly current.

2. Getting started

  1. Install once, in the project folder: 
    python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
  2. Create your account (you'll be asked for a password of at least 12 characters): 
    .venv/bin/python manage.py add-user yourname --admin
  3. For the AI steps, each person adds their own key after signing in, under My API keys (see section 13).
  4. Start the dashboard and open http://127.0.0.1:8765. That address shows the product page; Sign in (top right) takes you to the dashboard at /dashboard: 
    .venv/bin/python dashboard.py
  5. Fill in a project name and site URL, choose a crawl speed, and press Start sweep.

To restart the dashboard, press Ctrl+C in its terminal and run the start command again. Saved projects, runs and accounts are kept. A sweep that was running is lost.

3. Projects and runs

A project is one website plus its settings. Pick a project from the menu at the top of the dashboard, or press + New project. Save stores the settings. Start sweep saves and then runs.

Every sweep is a run, and every run is saved, including runs that were stopped or failed. The Run menu reopens any earlier run with all its data, charts and reports. While a sweep is in progress the menu shows “Live — running now”.

Only one sweep runs at a time across all projects. If one is running for another project, a banner says so and links to it.

Delete project removes the project folder: its settings, every saved run, and its remembered AI verdicts. You are asked to confirm, and it can't be undone.

4. How a sweep works

A run moves through seven steps, shown as cards across the top of the dashboard.

The seven steps of a sweep

DiscoverReads robots.txt and the sitemap. The sitemap supplies page addresses and last-edited dates.No
CrawlFetches pages, starting from the sitemap and following links within the site, up to the page limit. Menus, headers and footers are removed before analysis.No

The first four steps cost nothing and need no API key. Without a key, the AI steps are skipped and everything else still works.

5. Crawl speed and throttling

Sites block crawlers that hit them hard. The sweep is built to be a light, steady visitor.

Crawl speed presets
SpeedGap between requestsExtra pausesAbout 200 pages
Human-paced4–12 seconds, random8% chance of a 20–45 second pause35 minutes
Polite (default)1.5–4 seconds4% chance of an 8–15 second pause11 minutes
Standard0.4–0.8 secondsNone2 minutes
CustomYour own minimum and maximumNoneShown on the form

Link checks add time on top of the page count.

Whatever the speed:

  • One request at a time. Only one request to the site is ever in flight.
  • Automatic slow-down. If the site answers 429 (too many requests) or 503 (unavailable), the crawler waits as long as the site asks (its Retry-After, up to five minutes), doubles its gaps, and tries once more. After ten normal responses in a row it speeds back up.
  • robots.txt is obeyed, including any Crawl-delay, which becomes the minimum gap.
  • Honest identity. Every request says NightlySweep/1.0 (site health audit …), so the web team can see exactly who is visiting. The crawler does not pretend to be a person's browser.
If a site still blocks the crawler, use Polite or Human-paced and ask the site owner to allow the NightlySweep user agent. That is more reliable than any disguise, and on a public-sector site it is the right thing to do.

The line under the step cards reports how the crawl went, for example “2 reading pauses · slowed down 1× when the site pushed back”.

6. Stale and outdated content

How a page's age is measured

A page's age is the time since its last edit. The date comes from the sitemap's <lastmod> or, failing that, the page's Last-Modified header. Pages that publish neither are shown as “No date”. A page is stale when it is older than the project's “Stale after” setting.

Some content systems report every page as edited “now”, which makes everything look fresh. If the Content age chart puts nearly every page under 3 months, check whether the site's dates can be trusted.

Outdated wording

A page can have a recent date and still be out of date. The sweep reads every page for dates that have already passed but sit next to forward-looking words such as upcoming, will be held, deadline, register, closes, join us, until or apply by. It recognises dates written as “May 15, 2024”, “15 May 2024”, “2024-05-15” and “5/15/2024”.

Each match is shown with the surrounding sentence and the date highlighted. This check is free, and pages it catches are sent to the AI first.

The Stale & outdated report

Lists every page that is stale, has outdated wording, or has an expired event, oldest first. Each row shows the section of the site, the last edit, the signals found, the AI verdict, and the evidence. “Old, but the text shows no sign of being out of date” means the page is merely old, which is often fine.

7. Dead pages, broken links, expired events

Dead pages
Addresses that answer 404 or 403. They are not counted as crawled pages. The report lists which pages link to each one, so you know where to fix the link.
Failed to load
Other errors, such as 500 errors or timeouts. These aren't counted as crawled either, and appear as their own tile only when there are some.
Broken links
Links on a crawled page that lead to an error, including links to other websites.
Expired events
Events described in the page's structured data (schema.org Event) whose end date has passed.

8. AI triage

Flagged pages, up to 120 per run, are sent to the model in batches of eight with their title, last-edited date, forms, email addresses, outdated dates, expired events and text. Pages with outdated wording or expired events go first, then stale pages, oldest first.

The model is told that age alone is never evidence, to use unclear freely because a wrong “dead” costs a web team more than an honest “unclear”, and to quote its evidence word for word from the page.

Dead
Describes something that has ended: a closed application window, a past event presented as upcoming, a programme that was retired.
Unclear
The text doesn't say. Someone who knows the programme should look.
Live
Still true, even if old. Charters, ordinances, contact pages and reference material are normally live.

Choosing the AI provider

Each project picks its provider. Both AI steps, triage and contradictions, use it. The run header shows which model a run used. A sweep always uses the API keys of the person who started it, saved under My API keys. Without a key for the chosen provider, the AI steps are skipped and the crawl still runs.

Gemini, OpenAI, Groq, OpenRouter, Ollama and LM Studio

  1. Save your key under My API keys. Local apps need no key.
  2. Choose the service under AI provider. The line below the form says whether its key was found.
  3. Press Load models, then pick a model from the Model box.
  4. Press Test connection. Service model lists can include models retired for new accounts. If so, the test shows the service's message, which usually names the replacement.

Other (custom endpoint)

Use any other service that accepts the OpenAI chat-completions format. Choose Other (custom endpoint) under AI provider and fill in:

Endpoint URL
The service's base address. /chat/completions is added for you.
Model name
Exactly as the service spells it.
Your API key
Pick one of your saved keys whose name ends in _API_KEY or _TOKEN. The key itself never goes in the form or the project. Choose “None” for local models.

Save the key under My API keys first, using Another service, so it appears in the list. Press Test connection to send a one-line request and see the reply, or the exact error, before you run a sweep.

  • Only your own keys are used. The dashboard never uses the server's keys or anyone else's, so a custom endpoint can only ever receive a key you saved yourself. Your Anthropic and xAI keys can't be given to a custom endpoint, to prevent mistakes.
  • Newer OpenAI models want max_completion_tokens instead of max_tokens. The dashboard notices and retries automatically.
  • Requests to these services wait up to five minutes, since local models can be slow. When a service is busy or rate-limited (429 or 503), the request is retried twice, honouring the service's Retry-After.
  • Small local models may not follow the instructions well. They can return malformed answers, which are skipped, or weaker verdicts. Compare a run against one from a hosted model before relying on it.
  • Changing the provider or model means earlier verdicts aren't reused (section 9), so the next run re-analyses every flagged page.

9. Reusing earlier verdicts

Each project remembers the verdict for every page the AI has judged. On the next run, a page that hasn't changed gets its earlier verdict back without an API call, marked “↺ reused from” and the date.

“Unchanged” means that everything the model would be shown is identical: title, text, forms, email addresses, expired events, and the dates on the page that have already passed. So a page is judged again when:

  • any of its wording changes;
  • one of its dates passes. An untouched page reading “Registration closes November 1” is looked at again once November 1 is behind us;
  • the AI provider or the instructions given to the model change.

Untick Reuse AI verdicts for unchanged pages for a run to make the AI look at every flagged page fresh. The memory is stored in projects/<project>/analysis.json and is deleted with the project.

Contradiction results are never reused. The contradiction check runs across the whole site every time, because a page that hasn't changed can start contradicting one that has.

10. Contradictions

Step 1: group related pages (no AI)

Comparing every page with every other page would cost too much, and most pairs are unrelated. So the sweep first finds, for each page, the words that are distinctive to it, ignoring words used across most of the site. Pages that share many distinctive words are paired, and the most similar pairs are built into groups of two to four pages. Each group is labelled with its shared words, for example “permits, permit, building”.

Step 2: the AI compares each group

Each group is sent with the full text of its pages. The model looks for statements that can't both be true about the same thing (fees, deadlines, dates, hours, phone numbers, addresses, eligibility rules, requirements, named officials), across the pages and within each page. It is told that different programmes, years or audiences are not contradictions, that an old date alone is not one, and to leave out anything it is unsure of.

Step 3: every quote is checked

Each contradiction must quote both statements word for word. The sweep searches the actual page text for both quotes and discards any claim it can't find. The report says how many were discarded. Everything you see is two real sentences from the site.

Severity

High
A resident acting on the wrong statement could pay the wrong amount, miss a deadline, go to the wrong place or call the wrong number.
Medium
Confusing, but low consequence.
Low
Cosmetic.

Limits to know about

  • By default 12 groups are compared, so at most 48 pages. Raise “Groups to compare” (up to 40) for wider coverage, at one AI call per group.
  • Each page joins only one group, so a fact repeated on several unrelated pages can be missed.
  • Pages worded very differently may never be grouped together.
  • Pages under about 40 words are skipped, as is text beyond the first 6,000 characters of a page.

11. Reading the dashboard

Counts
The headline numbers for the run you are viewing. “Pages crawled” counts only pages that loaded successfully.
Content age
How many pages were last edited in each age range. Blue is recent, orange is stale, grey publishes no date. The dashed line marks your stale cutoff. The sentence above the chart gives the stale share and the median age.
Where the stale pages are
One bar per site section (the first part of the address, like /parks). The bar's length is the number of pages in the section, split into stale, recent and no-date pages. Sections with the most stale pages come first, so you know which department to talk to.
Trend across runs
Stale pages, broken links, dead pages and contradictions for each completed run of the project. It appears after the second completed run.
Findings mix
The split of AI verdicts, and contradictions by severity.
Activity
A timestamped log of every request, slow-down, verdict and contradiction. Long lines scroll sideways.

Hover over a chart for exact numbers, or open “View as table” beneath it for the same data as a table.

12. Reports and exports

The report has three views. Use the arrow keys to move between them once the view list has focus.

  • Stale & outdated: the stale-content focus described in section 6.
  • Contradictions: each conflict with the two quotes side by side, links to both pages, severity, and an explanation.
  • All issues: everything, including dead pages and broken links. Use “Show details” on a row for its broken links, expired events, or the pages linking to a dead page.

13. Accounts and sign-in

Everyone must sign in. There are two ways.

Username and password

  • Accounts are created from the command line (section 14). Passwords must be at least 12 characters.
  • Passwords are never stored. Only a salted scrypt hash is kept, in auth/users.json, which only the account running the dashboard can read.
  • After five wrong passwords in 15 minutes the account is locked for 15 minutes. An admin can unlock it straight away.
  • Password managers and pasting are fully supported.

Sign in with Google

For Google Workspace organisations. To turn it on:

  1. In Google Cloud Console, open APIs & Services → Credentials and create an OAuth client ID of type Web application.
  2. Add this Authorized redirect URI exactly: http://127.0.0.1:8765/auth/google/callback. Run manage.py status to see the address for your setup.
  3. Put the details in .env and restart the dashboard: 
    GOOGLE_CLIENT_ID=1234-abc.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-...
GOOGLE_ALLOWED_DOMAIN=yourcity.gov

Who can sign in with Google:

  • With GOOGLE_ALLOWED_DOMAIN set, anyone with a verified account in that Workspace domain. Their account is created on first sign-in. Several domains can be separated with commas.
  • Without it, only people an admin has added with --email.
  • A disabled account can't sign in with Google either.

The sign-in uses the standard secure authorisation flow (OpenID Connect with PKCE). The dashboard checks that the answer came from Google, was meant for this dashboard, is recent, matches the sign-in that was started, and belongs to a verified email in the allowed domain.

Open the dashboard at the same address as the redirect URI (127.0.0.1, not localhost). Otherwise the browser can't match the sign-in and you'll be asked to try again.

My API keys

Each person brings their own AI keys. Open My API keys in the top bar, paste a key next to its service and press Save. For a custom endpoint, use Another service and give the key a name ending in _API_KEY or _TOKEN.

  • Keys are encrypted with AES-256-GCM before they're saved, each sealed to its owner and its name. A key copied into someone else's account won't decrypt.
  • After saving, a key is never shown again; you see only its last four characters. It's never logged, written to results, or sent to the browser.
  • Your keys are used only for sweeps, model lists and connection tests you start, and only sent to the service they belong to. Administrators can't read them from the dashboard.
  • The encryption's master key comes from the SECRETS_KEY setting, or locally from auth/secret.key, created on first use. If it's lost or changed, saved keys can't be read and each person saves theirs again. Keep it backed up and private.
  • Removing an account also removes its keys.

The command-line scripts (sweep.py, triage.py, agent.py) still read keys from .env, because they run as whoever starts them.

Sessions

A sign-in lasts until you press Sign out, or after 24 hours without using the dashboard, and never longer than 30 days. Restarting the dashboard does not sign anyone out.

14. Admin command line

Anyone who can run commands in the project folder can manage accounts, without signing in. This is the admin override: use it to create the first account, reset a forgotten password, or get back in if you're locked out. Changes apply to a running dashboard immediately.

.venv/bin/python manage.py add-user andy --admin          # asks for a password
.venv/bin/python manage.py add-user sam --email sam@city.gov --google-only
.venv/bin/python manage.py set-password andy              # reset; also unlocks and signs out old sessions
.venv/bin/python manage.py unlock andy
.venv/bin/python manage.py login-link andy                # one-time sign-in link, valid 10 minutes
.venv/bin/python manage.py disable sam                    # blocks the account and signs it out
.venv/bin/python manage.py enable sam
.venv/bin/python manage.py remove-user sam
.venv/bin/python manage.py sign-out                       # everyone, or: sign-out andy
.venv/bin/python manage.py list                           # accounts, how they sign in, locked or not
.venv/bin/python manage.py status                         # Google settings and redirect URI
.venv/bin/python manage.py keys list andy                 # a user's saved key names (never the keys)
.venv/bin/python manage.py keys import andy               # encrypt the AI keys in .env into andy's account
.venv/bin/python manage.py keys remove andy GEMINI_API_KEY

login-link prints an address that signs that person in once, then stops working. It expires after 10 minutes (change with --minutes). Use it when someone is locked out and can't wait, or when Google sign-in is down.

For scripts, add-user and set-password accept --password-stdin.

15. Data, privacy and safety

  • Read-only. The sweep never submits forms, signs in to the target site, or changes anything on it.
  • Sent to the AI provider: the title, date and text (up to a few thousand characters) of flagged pages, and the text of pages compared for contradictions. These are public pages. With a custom provider this goes to whatever endpoint you set; with a local model it never leaves your machine. Nothing else is sent.
  • Stored locally in the project folder:
    • projects/: settings, runs and remembered verdicts.
    • auth/: accounts, sessions and everyone's encrypted API keys, readable only by your user.
    • .env: server settings such as Google sign-in, and the API keys used by the command-line scripts. Dashboard users' keys are kept encrypted in auth/, not here.
    Keep .env and auth/ out of version control. The included .gitignore does this.
  • Local only by default. The dashboard listens only on this computer (127.0.0.1). To share it with a team, put it behind HTTPS (a reverse proxy) and set COOKIE_SECURE=1 in .env. Don't expose it over plain HTTP.
  • Browser protections. Cookies are HttpOnly and SameSite. Requests from other sites are refused, the dashboard can't be framed by another site, and addresses aren't leaked to other sites.

17. Accessibility

The dashboard, this page and the sign-in page are built to meet WCAG 2.2 level AA, which includes all of WCAG 2.1 AA, the level the U.S. ADA Title II rule requires of public-sector web content. WCAG 3 is still a draft and has no AA level yet.

  • Everything works with a keyboard. A “Skip to main content” link comes first, focus is always visible, and the report views are tabs you move between with the arrow keys.
  • Text and controls meet contrast minimums in light and dark mode. The page follows your system's dark-mode setting.
  • Every chart has a text description and a “View as table” equivalent, and colour is never the only way information is shown.
  • Screen readers hear when a sweep starts, moves to a new step, and finishes. Form errors are announced.
  • Pages reflow to a narrow phone width. Wide data tables and the activity log scroll sideways within their own area.
  • Animations stop if your system asks for reduced motion. Hover tooltips close with Esc.
  • Sign-in needs no puzzle or memory test: password managers, pasting and Google sign-in all work. Sessions last at least 24 hours, so nothing times out mid-task.

Automated testing with axe-core is part of how these pages are checked. Automated tools catch only part of WCAG, so manual review with a screen reader remains worthwhile.

18. Troubleshooting

“No accounts yet” on the sign-in page
Run .venv/bin/python manage.py add-user yourname --admin, then reload.
Locked out, or forgot the password
manage.py set-password yourname resets and unlocks the account. For immediate access, use manage.py login-link yourname.
“That sign-in didn't start in this browser”
Open the dashboard at the address in the redirect URI (http://127.0.0.1:8765) and try Google sign-in again.
Google says redirect_uri_mismatch
The redirect URI in Google Cloud must match manage.py status character for character.
The AI steps were skipped
The person who started the sweep has no key saved for the project's provider. Add one under My API keys. The project form warns about this before you start.
“Saved, but can't be read”
The server's encryption key (SECRETS_KEY or auth/secret.key) changed. Save the key again.
A custom provider doesn't work
Press Test connection. It shows the endpoint's own error, such as a wrong model name or an invalid key. “No … saved under My API keys” means you haven't saved a key for that service yet.
The crawl is very slow
Check the speed setting and the pace line under the step cards. “Slowed down” means the site asked for it. Respect that, or ask the site owner to allow the crawler.
Everything shows as recently edited
The site reports the current time as every page's last edit. Outdated-wording detection and AI triage still work; only age-based staleness is affected.
“Address already in use” when starting
Another copy is running. Stop it with pkill -f dashboard.py, then start again.

19. Querying results from an agent

mcp_server.py is a read-only MCP connector onto everything under projects/. An MCP-aware agent — Claude Code, Claude Desktop, or anything else that speaks MCP — can ask it about saved sweeps: what a run found, how two runs compare, which pages a model judged dead. It has no tool that starts a sweep, changes a setting, or writes anything; Read is its only open claw, same as the rest of this project.

It only runs over stdio, spawned by a client already on this Mac, so there is no network listener and no separate sign-in: your file permissions are the access control.

Claude Code

claude mcp add -s user nightly-sweep -- /absolute/path/to/Sweeper/.venv/bin/python /absolute/path/to/Sweeper/mcp_server.py

-s user registers it for every project, not just this one. Then, in a new session, ask something like “What did the last Suffolk VA sweep find?” or “Compare the two most recent Martin County runs.”

Claude Desktop

Add a custom connector in Settings pointing at the same command and arguments as above. The exact menu differs by app version — look for Settings → Connectors or Developer → Edit Config. Older versions use a JSON file instead:

{ "mcpServers": { "nightly-sweep": {
    "command": "/absolute/path/to/Sweeper/.venv/bin/python",
    "args": ["/absolute/path/to/Sweeper/mcp_server.py"] } } }

What it can answer
